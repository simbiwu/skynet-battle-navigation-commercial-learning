# Shared 发布资产

`shared/` 保存 Unity、Server 和离线工具必须共同认同的版本化合同。它解决的问题是：开发、构建和部署可以发生在不同机器，但各端仍能通过同一个 Git 提交得到完全一致的协议和导航资产。

这里保存的是可发布输入或可验证生成物，不是某台机器的实时交换目录：

- `protocol/`：唯一 `.proto` 源、固定工具版本，以及供各端消费的协议生成物；
- `navigation/`：Unity Authoring 已验证并发布的 BMAP 与 manifest。

Unity Bake 只会更新当前工作区的候选文件。必须完成验证、提交和推送，Server 所在机器再拉取同一提交，新的资产才进入 Server 工作区。生产部署可以把 `server/` 与所需 `shared/` 一起打包；运行期不依赖 Unity 工程、Windows 盘符或网络共享目录。

生成物必须与源文件在同一次提交中更新。评审与 CI 应同时检查业务版本、格式版本和 SHA-256，不能用“文件能加载”替代版本一致性。
