# FlyWow Gateway 本机 Benchmark：TCP 阶段报告

日期：2026-10-03（Asia/Shanghai）。状态：TCP 全档位完成；WebSocket 容量测试尚未执行；benchmark 已停止。

## 结论与建议

**建议以4096连接作为下一步默认配置候选，8192作为探索配置，不直接把8192设为默认。生产配置本轮未修改，仍为1024。**

本机真实TCP握手、Protobuf编解码、本地异步Handler链路下，4096连接、8192请求/秒的30秒测量零响应错误，RTT p99为5.5ms，计划发送到响应p99为17.3ms。4096连接另完成5分钟持续运行和3轮同进程连接周转，连接计数与FD在关闭后均回到基线。

8192连接能够全部建立，但延迟明显恶化：8192请求/秒时RTT p99为17.7ms，计划发送到响应p99为57.8ms；目标16384请求/秒时RTT p99为521.9ms，额外排空1.611秒，压测客户端接近单核满载。**这不是已验证的稳定容量，也不能据此定位为Gateway自身极限。**

4096候选仅有TCP本地框架链路证据。WebSocket容量、跨进程业务链路、重复多轮容量确认和2小时soak未完成，不能宣布正式生产容量验收通过。

## 本轮范围与停止原因

链路：Python asyncio客户端 → 真实密码握手 → FlyWow Gateway → 本地测试Handler → Gateway → 客户端。测试复用宿主QueryCell消息形状，Handler回显map_id标记，不执行地图查询或Battle。小型Envelope约12～13字节，不代表256B或大包场景。

当前协议Envelope只有protocol_version、command、body。每连接最多一个在途请求，以响应map_id校验归属和内容。没有伪造request_id或绕过握手。

TCP测试完成后，修正吞吐统计口径的编辑命令发生SyntaxError。该命令未写入文件，WebSocket尚未启动；按用户“有错误就停下来，不要继续测试”停止。停止后仅只读核对数据与写报告，没有再执行测试。TCP原始数据及源文件未受该编辑命令影响。

## 测量方法与吞吐口径

连接档位256、1024、2048、4096、8192；每档独立Skynet进程，先测无客户端基线、完成握手，再预热5秒。每个负载段30秒，测试固定总量2000请求/秒、每连接1次/秒和2次/秒。

同时报告：
- RTT：实际调用发送到收到并校验完整响应。
- 计划发送延迟：计划发送时刻到完整响应，包含客户端迟发和排队。
- RSS：Skynet进程物理驻留内存；客户端RSS独立记录。RSS不含全部内核Socket内存，不能当成整机总连接成本。
- Lua内存：每5秒使用公开Skynet debug MEM读取，未强制GC。
- CPU：累计CPU秒换算，单核满载=100%，不是12核整机比例。
- RSS峰值：每秒采样的最大值，可能漏掉更短暂峰值。
- 延迟：0.1ms有界直方图，分位数为桶上界；超过2秒归末桶，max保存实际值。

原始TCP JSONL的successful_qps为“完成样本数 / 计划30秒”，包含末端排空，不能直接当实际吞吐。本报告统一换算为“完成样本数 / (30秒 + drain_s)”。因drain_s保留3位小数，换算为近似值。拥塞点不能用计划窗口计数宣称达标。浮点调度可能多出1个边界样本，不作为额外容量收益。

响应不匹配、超时、Service堆栈、Gateway ERROR/WARNING或进程退出会立即中止当前测试。故障注入已验证该保护，完成后再次只读扫描全部正式TCP日志。

3轮均零响应错误，连接计数归零、FD回到8。RSS与Lua内存波动，最后一轮仍高于初次关闭；轮数较少，不能排除周期性积累或长期泄漏。周转后的计划发送p99达到19.7～23.7ms，短期重新建连会影响尾延迟，4096默认候选也应继续验证真实连接周转负载。
