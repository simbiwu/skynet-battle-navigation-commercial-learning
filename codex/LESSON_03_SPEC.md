# Lesson 03 Spec：两种独立的实时战斗同步方案

第三课最终版由两份彼此独立的实操文档组成，按帧同步、状态同步的顺序学习：

1. [帧同步版实操](../docs/Skynet_BattleNavigation第三课_帧同步版_实操.md)
2. [状态同步版实操](../docs/Skynet_BattleNavigation第三课_状态同步版_实操.md)

两份实操都从 Lesson 2 已完成基线开始。旧版第三课实操不作为实现基线；只提取仍适用的导航、Server 权威、AI、技能、事件、状态观察和验证知识。

## 共同课程边界

- 目标是具备商业实时战斗所需的完整核心边界，同时保持玩法内容简单；不以课程样例规模删去权威、快速响应、生命周期、失败恢复、版本合同和可验证性。
- 帧同步与状态同步是两套独立方案，可以有不同玩法和战斗模拟实现。不得为了代码复用增加统一 Battle Core 或改变各自网络模型。
- Server 决定正式位置、技能合法性、命中、伤害、HP、死亡和战斗结果；客户端只能提交意图并负责预测/表现。
- 两版都包含移动、简单 AI、基础通用 Skill Runtime、技能冷却/距离/目标规则、表现与逻辑效果的边界、地图/配置版本和 Unity/Server 联调。各版具体技能与玩法见对应实操。
- 复用现有 FlyWow Gateway、导航资产和公开合同；不复制 framing、接入层或导航实现。低延迟实时数据通道由 FlyWow Gateway 管理，若现有公开合同不满足帧/状态同步的数据报需求，在对应实操中按抽取规范扩展 FlyWow；Battle 层拥有各自的命令、帧确认、事件与恢复语义。Battle/Skill 是否抽入 FlyWow 在完成并验证后按抽取规范评估。
- 文档编写遵循 `docs/CODEX_TEACHING_GUIDE.md`；源码及教程中的可复制代码遵循 `.agents/skills/skynet-battle-navigation-coding-standard/SKILL.md`。

## 当前帧同步玩法边界

玩家操作地面单位；Server控制地面敌人与可主动升降的飞行敌人。飞行高度是可恢复整数状态，不能固定高度；客户端按确定性Core复现AI，不拥有正式敌人控制权。地图仍为已发布2.5D地表资产，地面寻路与空中移动规则分开；完整三维空域碰撞需对应资产，当前不冒称已实现。三种技能表现包括瞬发、表现弹丸与逻辑弹丸，目标类型和高度参与正式规则。帧同步实操正文已补齐；状态同步版仍保留蓝图，后续独立编写。

## 完成条件

每个版本分别具备独立的代码与配置、真实客户端/服务端链路、固定且可复现的验证、正常与失败路径说明、性能/网络条件下的验证记录。完成一版不代表另一版完成。具体验收用例与阶段顺序以对应实操文档为准。

## 版本关系

本 Spec 取代旧版 Lesson 3 的“同一个模拟内核同时支持在线与批量回放”及单一玩法约束。Lesson 2 离线 Battle/Replay 基线继续保留；两份新实操分别建立帧同步和状态同步链路。
